# Compete on the decision, not another meeting summary

The strongest positioning for this project is **“Catch the contradiction before the commitment.”** A narrow read-only verification agent is more defensible than claiming a universal meeting assistant. Winning cannot be guaranteed, and eligibility is a prerequisite, not a score to optimize around.

Use #strands-decider-2b and the relevant pattern tag; this edition uses #tool-selection. Recheck rules and deadline before submitting.

## The strongest demonstration

1. Show one short contextual confirmation, one approval conflict and a restrained conditional proposal.
2. Inspect the decision: real checkpoint, selected tool, confidence, provider status, usage and latency.
3. Open exact source evidence, including its revision. Explain that sources are fixtures while inference is real.
4. Apply the explicitly simulated approval revision. Retire only the obsolete warning; preserve its evidence snapshot.
5. Show an actual measured failure or unnecessary clarification and the reusable pattern. Finish with real repository/video links.

Prefer Script or Manual for reliable recording. Microphone recognition is a separate browser service, not proof that either model works. Do not show offline rehearsal as a qualifying inference demo.

## Priorities before submitting

Retain eligibility confirmation → local real-model smoke test → actual AWS execution → measured validation report → concise recording/article → final links and tags. Do not spend the remaining time on extra integrations, decorative dashboards or unsupported accuracy claims. A reproducible small system with a visible meaningful decision is the strongest case this implementation can make.
